# shell-guards

Self-contained agent-guards plugin for terminal command hygiene.

## Blocks

- Recursive `find`, `grep -r`, `rg`, `ag` and `fd` over the whole Hermes home, `installs` or `benchmarks` (about 2.5 million files, minutes per call). Searches inside `skills`, `memories`, `plugins`, `profiles/<name>`, `kanban` and `hermes-agent` pass, and so does `find` with `-maxdepth` 2 or less. Every profile.
- `git stash` writes (push, pop, drop, apply, clear; `list` and `show` pass), for workers. The stash stack is shared by every worktree of the repository, so a pop or drop can restore or destroy another lane's changes or your own. Compare against the base with `git show HEAD:<file>`, `git diff` or `git worktree add /tmp/<name> HEAD`.
- `process_manage` `poll`. `wait` returns the moment the process exits (a `timeout` shorter than the configured limit is lifted to it), `log` reads output, and a `notify=true` job sends its completion as a message.
- Foreground `sleep` of 5s or more, or a `for`/`while`/`until` polling loop holding a `sleep` of 3s or more. The block message gives the exact call shape: `terminal(command=<the same command/loop>, background=true, notify=true)` (loops: `notify=[<ready pattern>]`). Heredoc bodies and quoted strings are exempt.
- `gh pr merge` without `--match-head-commit` — the block message shows the corrected call: add `--match-head-commit <head-sha-of-the-pull-request>` (read the sha from `gh pr view <number> --json headRefOid`).
- `osascript` — desktop automation goes through ego-browser.
- `gh auth switch`, `gh auth login`, `gh auth logout`, `gh auth refresh` — they change the shared active account for every Hermes process, and Hermes reads its Copilot token from the active account. To act as another account, set it in the command itself: `GH_TOKEN=$(gh auth token -u <user>) <command>`; the default active account is `acme-bot`. `gh auth status` and `gh auth token` stay allowed.
- `git push` with a bare `--force`/`-f` — use `--force-with-lease`.
- Recursive deletion of a live Hermes home (`rm` with a recursive flag, `find -delete`, `rsync --delete` on a protected destination, python `rmtree`-family calls in `-c` payloads or heredocs) aimed at `$HERMES_HOME`, `~/.hermes`, any user's literal absolute form, the `profiles` subtree or an ancestor of these, including stages reached through a runner chain after a pipe. Deeper nests and quoted/heredoc prose stay allowed; for tests create a throwaway home with `mktemp -d` inside the scratch workspace and delete the printed directory by its literal path.
- A `paas-promote` workflow dispatch targeting `des` without the `auto-approval` label in `LABELS` — the deployment pull request would stay open until someone notices. The block message names the corrected `-f LABELS=...` flag.
- A `gh pr create --base <b>` (or `az repos pr create --target-branch <b>`/`-t <b>`) where `<b>` is a long-lived integration branch (`main`, `master`, `develop`, `trunk`, `dev`) other than the repo's real default branch, and a new branch started at one (`git checkout -b x <ref>`, `git switch -c x <ref>`, `git worktree add ... -b x <ref>`, `git branch x <ref>`). The default branch is read from `refs/remotes/origin/HEAD` in the command's repo (workdir, `cd`, `git -C`, or the local clone matching `gh --repo`/`-R`); no network, and an absent symref fails open. A stacked PR to a feature/release branch and an omitted base pass. The block message names the real default branch and the corrected command (`Run instead: ...`).
- `kanban_attach` with more than 256 characters of inline base64 — the model transcribes those bytes and corrupts them; the block message shows the replacement arguments (`artifacts=[absolute path]`, then sha256-compare the stored file).
- An unsigned `git commit` (or `git commit --amend`) in a repo that requires signed commits — decided locally: a `github.com` origin whose `origin/<default>` last-20 history is >= 90% signed (Azure remotes never require it). The block message shows the exact command with `-S` inserted and the three `git config` lines that make signing permanent (the repo's own `gpg.format` and `user.signingkey` when configured). Verdict cached per repo for 10 minutes; fails open on every doubt.

## Requires

- A `terminal` call with `background=true` that is not a long-lived server (vite, http.server, uvicorn, gunicorn, local proxies, databases, containers — detected conservatively from the final statement) declares an outcome channel: `notify=true`, a non-empty notify pattern list, or a positive `heartbeat`. When it declares none, the hook turns `notify=true` on instead of blocking (worker setups), and the block message names the exact call shape `terminal(command=<same command>, background=true, notify=true)`. Pty sessions are exempt.

## Rewrites

- The poll-only promoted-process note from Hermes core ("This session cannot receive completion notifications, so poll it with process(action=\"poll\", session_id=...) until it exits") is rewritten by a `transform_tool_result` to the event-driven instruction consistent with the guards: retrieve the outcome with `process_manage(action="wait", session_id=...)` or `process_manage(action="log", session_id=...)`, and when the wait returns interrupted with no new output, end the turn and wait again in a later turn — never poll, never sleep. The note that already carries `notify_on_complete=true` (the completion arrives as a notification) keeps its poll "if you need it sooner" hint.

## Normalizes

- Empty-string optional Kanban arguments (`assignee` in `kanban_list`, `completion_contract` in `kanban_create`) become absent.
- A Kanban `task_id` sent as the literal `$HERMES_KANBAN_TASK` becomes absent, so the tool falls back to the worker's own task.
- A `skill_view` name of the form `x:x` becomes `x`.
- A `terminal`/`process_manage wait` timeout above the call deadline (resolved from `timeouts.tools.sequential_call`, else `timeouts.tools.concurrent_batch`/`HERMES_CONCURRENT_TOOL_TIMEOUT_S`, default 420 s) is clamped to 15 s below it (405 by default), before the tool runs. Verified live against `tools/terminal_tool.py`: the host kills a sequential tool at the deadline with `Error executing tool 'terminal': timed out after Ns` and returns nothing, so a foreground `terminal` call whose `timeout` exceeds the deadline always dies there — the tool's own behavior above `FOREGROUND_MAX_TIMEOUT` (600 s by default, `TERMINAL_MAX_FOREGROUND_TIMEOUT`: the command is promoted into a tracked background process with `notify_on_complete=true` and a `promoted_from_foreground` note) is never reached, and the clamp keeps that path intact for calls that do not exceed the deadline (a `background=true` call is not rewritten at all, and `timeout=600` at the default deadline is rewritten to 405 while `timeout=300` passes). The pre-existing `process_manage` `wait` default clamp (5 s below the deadline, from `TERMINAL_TIMEOUT`) stays authoritative for waits between the two margins, and `wait` timeouts above `TERMINAL_TIMEOUT` are still reported by the tool itself as `clamped to configured limit`. A rewritten call, run through the gate again, changes nothing (idempotent); a non-integer, boolean or non-positive `timeout` and an unresolvable deadline all pass untouched (fail open).
- A `terminal` result whose own timeout — reached only after the pre-call rewrite above — kills it (`[Command timed out after Ns]` at exit code 124 with N equal to the rewrite cap, 405 by default) gets one appended line naming the exact replacement call: `terminal(command=<the same command>, background=true, notify=true) returns at once and its completion arrives as a message - never re-issue this same foreground call.` The note rides `transform_terminal_output` (runs inside the terminal tool, `tools/terminal_tool_result.py` `finalize_foreground_result`) because the host's own deadline kill produces a result no transform hook ever sees. The rewrite itself stays silent (`pre_tool_call` merge directives carry no message), and a call the host still kills at the deadline — one that predates the rewrite, or a deadline that shrank under a session — therefore leaves no note: the model sees only the host's `Error executing tool '<name>': timed out after Ns` line.

## Skill sizes

- Blocks `skill_manage`/`write_file`/`patch`(replace) calls that would push a skill markdown file over its limit (SKILL.md 6000, other skill `.md` 12000 characters; shrinking an over-limit file is always allowed). Flags after the fact a `terminal`/`execute_code`/unified-diff `patch` call that left one over its limit, and refuses on `pre_verify` to end the turn while a flagged file is still over it (re-measured at check time; at most two continuations per file per session).
- Flags after the fact a `terminal`/`execute_code`/unified-diff `patch` call that left one over its limit: the required action and the tree-split instruction are appended to the tool result, nothing is reverted. The instruction names the refactor route for a full index: a skill whose SKILL.md is already at its limit is split into more `references/<topic>.md` files so the new line fits, never left with the change dropped. A `terminal` call is flagged on `transform_terminal_output` (inside the terminal tool, before the result hook), so the flag survives alongside the `kanban-guards` delegation nudge when one lead call both crosses the nudge threshold and leaves a skill oversized; `execute_code`/`patch` are flagged on `transform_tool_result`. The flag is then enforced: `pre_verify` refuses to end the turn while a file flagged in the session is still over its limit.

Commands are matched at command-word position outside quoted strings, so mentions in strings, grep patterns and python bodies pass. The guards catch slips, not deliberate evasion, and fail open. `post_tool_call` is registered as a no-op placeholder hook; lifecycle and board gates live in the sibling kanban-guard plugins.
